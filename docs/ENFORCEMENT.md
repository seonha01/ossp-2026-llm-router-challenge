# 실행 오류와 규칙 집행

이 문서는 참가자 제출에 적용하는 실패 분류, 재실행과 실격 기준을
정의합니다. 모호한 실패를 참가자 책임으로 잘못 분류하지 않기 위한 기록·복구
절차는 [`OPERATIONS.md`](OPERATIONS.md)에 분리했습니다.

## 참가자 필수 요약

| 상황 | 처리 |
| --- | --- |
| 비용 예산 초과 | 해당 등급 0점 |
| 참가자 실행·선택 결과 오류 | 동일 실행 입력으로 최대 3회, 모두 실패하면 해당 등급 0점 |
| 운영자 인프라 장애 | 참가자 실행 횟수에 포함하지 않고 복구 후 재실행 |
| 금지 전략·격리 우회 | 증거 검토 후 전체 제출 실격 가능 |
| 이미지 사전검증 실패 | 컨테이너 실행 전에 접수 거부 |

## 예산 초과

예산 초과는 참가 자격이나 공정성 위반이 아닙니다. 정확한 Decimal 비용이
해당 등급의 한도를 조금이라도 초과하면 그 등급 점수만 `0`으로 계산합니다.
다른 등급의 실행과 점수에는 영향을 주지 않습니다.

## 실행·선택 결과 오류

다음은 참가 자격 위반이 아니라 해당 등급의 실행 실패입니다.

- 시간, 메모리, 프로세스·스레드 수, 로그 출력량 또는 출력 크기 한도 초과
- 비정상 종료 또는 강제 종료
- 출력 파일 누락
- UTF-8 또는 JSON 형식 오류
- 문항 누락·중복·추가
- 알 수 없는 모델 ID
- 잘못된 등급, 정책 ID 또는 입력 메타데이터
- 참가자가 출력 볼륨의 권한이나 내용을 바꿔 검사를 방해한 경우

등급별 공식 실행은 최초 실행을 포함하여 최대 3회입니다. 운영자는 처음에
고정한 동일 실행 입력을 모든 재실행에 사용합니다. 각 실행이 끝날 때마다 종료
상태와 출력 전체를 검증하고 첫 번째 유효한 결과를 즉시 사용합니다. 유효한
결과를 얻은 뒤에는 참가자 오류에 대한 추가 실행을 하지 않습니다. 세 번
모두 실행·형식 오류이면 그 등급 점수만 `0`으로 처리합니다.

## 운영자 인프라 장애

컨테이너 호스트, 저장소, 이미지 레지스트리, 평가 오케스트레이터 또는 입력
마운트 같은 운영자 측 장애로 프로세스를 정상적으로 시작하거나 결과를
검사할 수 없었다면 참가자 공식 실행 횟수에 포함하지 않습니다. 같은 커밋,
이미지 다이제스트, 입력, 등급과 자원 조건으로 다시 실행합니다.

운영자 장애가 반복되어 평가를 완료할 수 없으면 해당 등급을 `0`점으로 확정하지
않고 복구가 끝날 때까지 평가를 보류합니다. 세부 분류와 복구 절차는
[`OPERATIONS.md`](OPERATIONS.md#시간-초과와-상태-확인)에 기록합니다.

## 이미지 사전검증 실패

참가자 프로그램을 실행하기 전에 다음 항목을 검사합니다.

- 제출 커밋과 변경 불가능한 이미지 다이제스트의 대응
- `linux/arm64` 플랫폼
- 압축 계층 합계와 병합 루트 파일 시스템 크기
- 허용하지 않은 `VOLUME` 선언 여부

최종 크기 한도를 넘거나 `VOLUME`을 선언한 이미지는 참가자 컨테이너를 실행하지
않고 접수 단계에서 거부합니다. 이는 공식 실행 실패 횟수로 세지 않으며 자동
재시도하지 않습니다.

증거가 없거나 손상됐거나 제출 이미지와 대응하지 않는 경우에는 참가자
사전검증 실패로 단정하지 않고 운영자 인프라 장애로 평가를 보류합니다.

## 공정성 또는 참가 자격 위반

다음 행위가 소스, 의존성, 컨테이너, 파일 또는 실행 로그 감사에서 확인되면
한 등급의 실행 실패가 아니라 전체 제출 실격 사유입니다.

- 공개되지 않은 평가 자료·평가 실행 결과·메타데이터 사용
- 네트워크 접근 또는 외부 추론·모델 제공 API 호출
- 비공개 패키지, Git submodule, 모델 파일 또는 다운로드 경로 사용
- 제출 소스와 컨테이너 내용 또는 실행 프로그램의 불일치
- GPU, 권한, 파일 시스템이나 평가 환경의 격리 조건 우회
- 운영자가 고정한 평가용 모델 또는 답변 생성용 대형 모델 실행

실격 판단은 재현 가능한 증거와 적용한 규칙을 실행 기록에 남기고 운영자가
검토합니다. 단순한 예산 초과나 형식 오류를 공정성 위반으로 확대하지
않습니다.

## 포함 파일의 권리와 고지

모델·토크나이저·사전·학습 자료의 라이선스 근거나 필수 고지가 빠진 제출은
접수 검증에서 보완을 요구하고, 보완 전에는 평가 대상으로 받아들이지
않습니다. 접수 마감까지 근거를 제출하지 못하거나 허용 라이선스·재배포
조건을 충족할 수 없는 파일은 참가 자격 위반으로 처리합니다. 권리 상태나
컨테이너 내용을 고의로 허위 기재한 경우에는 공정성 위반으로 전체 제출을
실격 처리할 수 있습니다.

## 감사 재실행

운영자는 동일한 프로그램에 문항 ID와 순서를 바꾼 입력을 제공하거나
컨테이너 내용, 의존성, 모델 파일과 파생 자료를 검사할 수 있습니다.
규칙 준수를 확인하는 감사 재실행은 점수를 다시 얻을 기회가 아니며 공식
최대 3회에 포함하지 않습니다.

감사에서는 프롬프트 내용이 같은 문항의 선택이 ID와 순서 변경 전후에
일치하는지 확인합니다. 사전에 공개하지 않은 의미 보존 변형을 사용할 수도
있지만, 표현 변형 전후의 선택 차이만으로 위반으로 판단하지 않습니다.
콘텐츠가 같은데 ID·순서만 바꿨을 때 선택이 달라지거나 문항별 조회 자료 또는
금지 정보 접근 흔적이 발견되면 추가 검토 후 공정성 위반 여부를 판단합니다.

ID·순서 감사에서 실행 오류나 선택 차이가 생겨도 자동 실격하지 않고 운영자가
근거를 검토합니다. 감사 입력 생성, 상태 기록과 운영자 장애 처리 절차는
[`OPERATIONS.md`](OPERATIONS.md#감사와-구조화된-기록)에 정의합니다.
