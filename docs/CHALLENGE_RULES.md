# 과제 규칙

## 한눈에 보기

- 현재 문항의 프롬프트 내용과 평가 등급만 보고 모델 하나를 선택합니다.
- 모델 호출, 답변 비교와 답변 확인 후 순차 승격은 지원하지 않습니다.
- 문항 ID, 입력 순서와 프롬프트 밖의 메타데이터는 모델 선택에 사용할 수
  없습니다.
- 공개 Train/Dev의 프롬프트·평가 결과와 공개 비용 정책은 학습과 최적화에
  사용할 수 있습니다.
- 예산을 넘으면 해당 등급 점수만 0점입니다.
- 공식 평가에서는 제출 이미지를 네트워크 없이 `linux/arm64`로 실행합니다.

## 목표

참가자는 프롬프트 내용만 사용하여 문항마다 다음 평가용 모델 프로필 중
하나를 고르는 라우터를 구현합니다.

- `ax31-light`
- `ax31`
- `axk1-think`

참가자는 모델을 실행하거나 모델 제공 API를 호출하지 않습니다. 라우터는 각
문항에서 모델 하나만 선택하며, 모델 답변을 실시간으로 받아 비교하거나
선택을 번복하지 않습니다.

## 용어

- **라우터 실행 입력**: 평가할 때 참가자 컨테이너에 전달하는 prompt-only
  JSON입니다.
- **라우터 선택 결과**: 라우터가 문항마다 선택한 `model_id`를 기록한
  JSON입니다. 모델 답변이 아닙니다.
- **공개 평가 결과(outcome)**: 공개 Train/Dev에서 모델별 품질과 비용을
  학습·계산하는 데 사용하는 별도 JSON입니다.
- **모델 답변**: 사전 계산에 사용한 생성 텍스트입니다. 공개 자료나 라우터
  실행 입력으로 제공하지 않습니다.

## 공통 32K 평가 조건

세 평가용 모델 프로필의 사전 계산 결과는 모두 32,768 토큰의 전체 문맥
한도에서 생성했습니다. 이는 모델별 문맥 용량 차이가 라우팅 성능에 영향을
주지 않도록 맞춘 과제 조건입니다.

`axk1-think`의 결과는 이 공통 32K 조건에서의 성능입니다. 더 긴 문맥이나 더
큰 추론 예산을 사용했을 때의 최대 성능을 뜻하지 않습니다.

정책의 `context_limit_tokens`는 이 생성 조건을 기록하는 생성 이력
(provenance)입니다. 참가자 라우터 컨테이너에서 다시 강제하는 입력 한도가
아닙니다.

## 라우터 실행 입력

실행 입력 객체는 다음 필드만 허용합니다.

- `schema_version`: 정수 `1`
- `challenge_id`: 실행 단위 식별자
- `split`: 실행 자료 구분자
- `episodes`: 한 개 이상의 문항

각 문항은 최대 128자인 불투명한 `episode_id`와 다음 둘 중 하나만
포함합니다.

1. 비어 있지 않은 문자열 `prompt`
2. `role`과 `content`만 가진 비어 있지 않은 `messages`

메시지의 `role`은 `system`, `user`, `assistant` 중 하나입니다.

`challenge_id`, `split`과 `episode_id`는 실행 검증과 선택 결과의 문항 연결에만
사용합니다. 세 값과 입력 순서는 모델 선택, 정책 전환, 학습 자료 조회나 다른
라우팅 특징에 사용할 수 없습니다. 같은 프롬프트와 등급의 선택은 이 값들이
바뀌어도 같아야 합니다.

## 라우터 선택 결과

`fast`, `balanced`, `premium` 등급마다 선택 결과 JSON 하나를 만듭니다. 객체는
다음 필드만 허용합니다.

- `schema_version`
- `challenge_id`
- `policy_id`
- `split`
- `tier`
- `decisions`

`decisions`에는 실행 입력의 모든 `episode_id`가 정확히 한 번씩 있어야 합니다.
각 결정의 `model_id`는 허용된 세 값 중 하나여야 합니다. 문항이 빠지거나,
중복되거나, 추가되거나, 알 수 없는 모델을 사용하면 검증에 실패합니다.

## 공개 평가 결과

공개 Train/Dev의 모델별 평가 결과는 `episodes[].models` 아래에 기록합니다.
각 모델에는 다음 네 값만 있습니다.

- `score`: `[0, 1]` 범위의 정확한 십진 문자열
- `num_generations`: 1 이상의 정수
- `input_tokens`: 1 이상의 정수
- `output_tokens`: 0 이상의 정수

모델 답변, 추론 과정, 정답, 종료 사유, 실패 횟수와 서비스 오류는 포함하지
않습니다.

## 사용할 수 있는 정보

공개 Train/Dev의 프롬프트와 모델별 평가 결과를 연결하여 학습·검증할 수
있습니다. 공개 비용 계수와 토큰 수로 모델별 비용을 계산하고 등급별 정책을
최적화하는 것도 허용합니다.

공개 자료에서 만든 분류기, 회귀 계수, 어휘·IDF, 토크나이저, 조회표, 검색
색인과 캐시를 제출 이미지에 포함할 수 있습니다. 정확한 프롬프트나 프롬프트
해시를 사용하는 공개 자료 조회도 허용합니다. 이미지에 포함한 모든 파일은 제출
저장소에서 출처와 라이선스를 확인할 수 있어야 합니다.

공식 평가 실행 시 문항별 모델 평가 결과나 실제 비용은 라우터에 전달하지
않습니다. 라우터는 현재 등급, 공개 비용 정책, 현재 프롬프트 내용과 공개
자료로 미리 만든 학습 파일만 사용하여 선택해야 합니다. 입력 프롬프트를
해시·n-gram·정규식·임베딩 등으로 변환하는 것도 내용 기반 라우팅입니다.

일반 용도의 사전, 토크나이저와 적법하게 재배포할 수 있는 소형 언어 처리
모델도 네트워크 없이 자원 한도 안에서 사용할 수 있습니다.

## 금지하는 전략

- 세 평가용 모델을 순차 호출하거나 생성 답변을 비교하는 방식
- 선택 뒤 재시도하거나 다른 모델로 바꾸거나 모델 답변 자체를 제출하는 방식
- `challenge_id`, `split`, `episode_id`나 입력 순서에 따라 모델 선택 또는
  정책을 바꾸는 방식
- 공개되지 않은 평가 자료·평가 실행 결과·메타데이터를 사용하는 방식
- 최종 평가 중 네트워크나 외부 추론 서비스를 호출하는 방식
- 제출 소스와 이미지가 다르거나 평가 환경의 격리를 우회하는 방식

공개 Train/Dev에서 검증한 것과 동일한 라우터 프로그램과 학습 파일을 최종
평가에도 사용해야 합니다.

## 점검과 위반 처리

운영자는 규칙 준수 여부를 확인하기 위해 제출 소스, 의존성, 컨테이너와 실행
로그를 검사할 수 있습니다. 문항 ID와 순서를 바꾼 입력으로 라우터를 다시
실행하여 ID·순서 의존성을 점검할 수도 있습니다.

예산 초과는 규칙 위반이 아니며 해당 등급 점수만 `0`으로 계산합니다. 시간,
메모리, 로그 출력량, 제한 출력 공간 초과와 잘못된 선택 결과 JSON은 해당
등급의 실행 실패로 처리합니다.

각 등급은 최초 실행을 포함하여 최대 3회 실행합니다. 첫 번째 유효한 결과를
사용하고 세 번 모두 실패하면 해당 등급 점수를 `0`으로 처리합니다. 운영자
인프라 장애로 무효가 된 실행은 이 횟수에 포함하지 않습니다.

금지 전략이나 격리 우회가 확인되면 전체 제출을 실격 처리할 수 있습니다.
자세한 분류는 [`ENFORCEMENT.md`](ENFORCEMENT.md)를 따릅니다.

## 최종 평가와 제출 저장소

참가자는 이 저장소를 fork한 공개 저장소의 커밋 SHA와 컨테이너 이미지
다이제스트를 제출합니다. 변경 가능한 이미지 태그는 받지 않으며, 저장소 이름과
전체 SHA-256 다이제스트를 함께 특정해야 합니다. 같은 이미지를 세 등급에 각각
실행하며 세부 인터페이스는 [`RUNTIME.md`](RUNTIME.md)를 따릅니다.

최종 점수는 라우터 선택 결과와 사전 계산 평가 결과를 결합해 오프라인으로
계산합니다. 실시간 비공개 순위표나 모델 답변 비교 단계는 없습니다.

제출 저장소에는 다음 요건을 적용합니다.

- 심사에 필요한 전체 소스코드를 포함해야 하며, 최종 제출 시점부터 평가가
  끝날 때까지 별도 권한 없이 공개 접근할 수 있어야 합니다. 수상팀은
  수상일로부터 5년 동안 제출 저장소를 공개 상태로 유지해야 합니다.
- 주된 코드 라이선스는 `Apache-2.0`, `MIT`, `BSD-2-Clause`, `BSD-3-Clause`,
  `ISC`, `0BSD` 중 하나여야 합니다. 참가자가 추가하는 라우터 애플리케이션
  코드와 라이브러리에는 이 목록과 `BSL-1.0`, `Zlib`을 허용합니다.
- 자료와 문서의 `CC-BY-4.0`, `CC-BY-SA-4.0`은 해당 파일의 귀속·고지와
  라이선스 의무를 충족할 때만 허용합니다.
- 기반 운영체제와 언어 런타임의 표준 구성요소는 상업적 이용과 재배포가
  가능하고 해당 고지·소스 제공 등 라이선스 의무를 충족하면 허용합니다.
  라우터 애플리케이션에 직접 결합하는 목록에 없는 copyleft 또는 사용자 정의
  라이선스는 사전 승인 없이 허용하지 않습니다.
- AI 모델을 사용한다면 최소한 가중치를 공개한 모델이어야 합니다. 파인튜닝한
  모델이나 직접 개발한 모델은 원본 라이선스가 허용하는 범위에서 별도 승인 없이
  받을 수 있는 공개 위치에 가중치와 실행에 필요한 코드를 게시해야 합니다.
- 모델·토크나이저·학습 파일은 상업적 이용, 이미지 안의 재배포, 필요한
  변형과 평가 목적 사용을 허용해야 합니다.
- 비공개 Git submodule, 패키지, 모델 파일이나 다운로드 경로에 의존하면 안
  됩니다.
- 제출한 커밋에서 컨테이너 이미지를 재현 가능하게 빌드할 수 있어야 합니다.
- 제출 커밋과 컨테이너 이미지 다이제스트의 대응 관계를 기록해야 합니다.
- 제한 밖 쓰기 공간을 만드는 Docker 이미지 `VOLUME` 선언은 허용하지
  않습니다.

제출 방법과 기술 제출 정보 파일은 [`SUBMISSION.md`](SUBMISSION.md)에
정의합니다.
